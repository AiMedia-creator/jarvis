# V3-Integrationsvertrag

Das neue Archiv ist die maßgebliche Python-Codebasis. Alte Jobs, Freigaben, Telemetrie, Tools, Elf-/Browser-Sprachmodus und CLI werden erhalten. `java-backend/` und `dashboard/` sind übernommene, geprüfte zusätzliche Module. Die native Oberfläche bleibt unter 8765, das React-Dashboard unter 8080.

Ein neuer lokaler Python-Bridge-Server läuft unter 8766 (`python -m jarvis.v3_bridge`). Nur Loopback-Hosts, gleicher Ursprung für Browser ausgeschlossen; Java verwendet `Authorization: Bearer $JARVIS_BRIDGE_TOKEN`. Der Token wird im gemeinsamen lokalen Launcher für beide Prozesse generiert und niemals im Frontend ausgeliefert. Java leitet Gespräche an den vorhandenen Python-Agenten weiter, statt eine isolierte zweite KI zu starten.

`POST /internal/generate` mit `{text, conversation_id, request_id}` liefert NDJSON: `{type:token,text}`, `{type:log,message}`, `{type:memory,...}`, `{type:done}` oder `{type:error,message}`. Jeder Callback ist generationserfasst. Java-Cancellation sendet zusätzlich `POST /internal/cancel` mit `{request_id}`; dies cancelt nur den erfassten Request, keinen neueren Zug. Java `Room`-ID wird als `conversation_id` verwendet. Kein privater LLM-Gedankengang wird übertragen.

`GET /internal/memory?q=...&limit=...` liefert `{facts:[], episodes:[], stats:{}, events:[]}`. Facts enthalten `id, content, category, updated_at`, Episoden `id, conversation_id, user_text, assistant_text, status, created_at`. Suchlimits max50; Inhalte sind vor Speicherung geheimnisbereinigt. `POST /internal/memory` mit `{content,category}` erzeugt eine explizite Notiz; `DELETE /internal/memory/{id}` löscht eine Notiz. SQLite ist die Single Source of Truth. Geheimnisse werden nie als Wissensnotiz gespeichert. Native UI und React erhalten Memory-Ansicht und Notizverwaltung; globale Löschung nur ausdrücklich und nicht automatisch.

Memory-Python-Modul bietet `store()` Singleton mit `search(query='',limit=12)`, `record_turn(conversation_id,user_text,assistant_text,status='completed')`, `remember(content,category='note',source='user')`, `forget(id)`, `stats()`, `events(limit=30)`, `recent_episodes(conversation_id=None,limit=10)`; IDs string. SQLite-Pfad folgt `config.data_dir()/memory.sqlite3`, austauschbar via Konfiguration. Suchergebnis dict IDs/Content, Stats dict facts/episodes. Module exportiert `snapshot(query='',limit=12)` in obigem API-Format. Memory-Agent integriert eigene passende Toolnamen, die diese Funktionen nutzen.

Demo-Modus `JARVIS_DEMO=true`: kein API-Schlüssel nötig; echte Persistenz/Recall wird trotzdem verwendet, Antwort und TTS-Testtöne explizit markiert. Echtmodus benötigt vorhandene Provider-Konfiguration. Server-VAD validiert 20-ms-PCM vor Transkription. Low-latency lokale Abbrüche passieren unabhängig von Provider-Roundtrips.
